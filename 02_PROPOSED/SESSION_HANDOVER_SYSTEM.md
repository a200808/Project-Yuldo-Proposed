# 장기 기획 세션 정기 Handover 운영안

- 문서 ID: YULDO-OPS-HANDOVER-0002
- 작성 AI: YULDO-AI-GENERAL
- AI 역할: GENERAL
- Prompt Version: GENERAL-v1.1
- 작성일: 2026-11-02
- 상태: [PROPOSED]
- 대상 저장소: a200808/Project-Yuldo-Proposed
- 관련 Confirmed: Project-Yuldo/00_AI_GOVERNANCE/SESSION_PROTOCOL.md, SESSION_INDEX.md, AI_RULES.md

## 1. 목적

장기 대화가 읽기 전용 전환, 세션 종료, 컨텍스트 손실, 새 채팅 분기 등으로 중단되어도 작업 상태와 결정 근거를 복구할 수 있게 한다.

Handover는 대화 전체를 복사하는 로그가 아니다. 다음 세션이 안전하게 작업을 재개하는 데 필요한 상태 요약이며, Canon을 대신하지 않는다.

## 2. 현재 구조 진단

이미 존재하는 기반:
- Confirmed SESSION_PROTOCOL은 세션 시작·작업·종료 절차와 Handover 갱신을 요구한다.
- Proposed 99_HANDOVER에는 AI별 인수인계 문서와 HANDOVER_TEMPLATE.md가 있다.
- Proposed 00_AI_WORKSPACE/WORKFLOW.md는 작업 전 Confirmed/Proposed 확인과 즉시 Proposed 기록을 요구한다.

확인된 빈틈 및 불일치:
1. 기존 세션 프로토콜은 세션 종료 시 갱신에 무게가 있어, 예기치 않은 중단 직전의 상태가 남지 않을 수 있다.
2. 기존 템플릿은 현재 작업·캐논·제안·미해결·다음 작업을 담지만, 체크포인트 주기, 중단 복구, 검증, 오래된 Handover 판별 기준이 충분하지 않다.
3. Confirmed SESSION_PROTOCOL은 99_HANDOVER/CURRENT_HANDOVER.md를 참조하지만 Proposed 저장소에는 AI별 문서가 중심이다. 두 저장소와 경로의 역할을 먼저 명확히 해야 한다. 이 제안은 Confirmed 경로를 임의 수정하지 않는다.

## 3. 제안하는 3단계 기록 체계

### A. 작업 중 체크포인트 (Checkpoint)
목적: 예기치 않은 중단에 대비한 최신 복구 지점.

다음 중 하나가 발생하면 담당 AI가 체크포인트를 기록한다.
- 실질적인 기획 대화 10~15회 왕복 후
- 작업 시작 후 약 30~45분이 지났을 때
- 사용자 결정 또는 중요한 답변이 나온 직후
- Proposed 파일을 새로 만들거나 큰 폭으로 수정한 직후
- 영역 간 의존성·충돌·REVIEW 요청이 생긴 직후
- 다른 AI/새 채팅으로 넘기기 전
- 사용자가 중단을 예고했을 때

위 시간·횟수는 [PROPOSED] 운영 기준이며, 자동 타이머나 플랫폼 기능이 있다는 뜻이 아니다. AI가 작업 흐름을 보고 수행한다. 체크포인트가 과도한 문서 작업이 되지 않도록 변경이 없으면 새 기록을 만들지 않고 기존 최신본을 갱신한다.

### B. 세션 종료 인수인계 (Session Handover)
목적: 정상 종료 또는 의도적인 새 채팅 분기 시 재개 정보를 전달한다.

세션을 끝내거나 역할/채팅을 넘기기 전에 담당 AI가 자기 AI별 Handover 문서를 갱신한다. 체크포인트보다 자세하게 작성하되 대화 전체를 전재하지 않는다.

### C. 비정상 중단 복구 (Emergency Recovery)
목적: 읽기 전용 전환, 오류, 강제 종료 등으로 마지막 인수인계를 작성하지 못한 경우.

새 세션은 마지막 체크포인트를 임시 복구 지점으로 사용한다. 체크포인트 이후 대화 내용이 사용자 화면에 남아 있다면 사용자가 제공한 해당 구간을 대조해 누락된 결정/제안을 복구한다. 보이지 않는 대화나 파일을 AI가 본 것처럼 추정하지 않는다. 복구 내용은 [PROPOSED]/[UNVERIFIED]로 표시하고 원문 확인 전 확정 기록으로 취급하지 않는다.

## 4. 기록 위치 및 파일 운영

- 기존 AI별 문서 99_HANDOVER/<AI별 파일>.md를 해당 AI의 최신 상태 문서로 유지한다.
- 각 AI는 자기 담당 문서만 갱신한다. 다른 AI의 인수인계 문서를 임의로 덮어쓰지 않는다.
- 기존 HANDOVER_TEMPLATE.md를 기반으로 아래 체크포인트 필드를 추가하는 방안을 제안한다.
- 체크포인트는 별도 파일을 무한히 생성하지 않고, AI별 최신 Handover 문서 안의 '최근 체크포인트' 영역을 갱신한다.
- 중요한 마일스톤, 사용자 결정, 장기간 유효한 인계, 중대한 충돌은 별도 스냅샷으로 보존할 수 있다. 모든 중간 체크포인트를 Archive에 쌓지 않는다.
- 전체 세션 현황을 찾기 쉽도록 99_HANDOVER/README.md를 인덱스로 사용한다. 필요하면 별도 CURRENT_HANDOVER 인덱스 파일을 Proposed에서 설계하되, Confirmed가 참조하는 경로와의 정합성을 먼저 검토한다.

## 5. 체크포인트 최소 필수 항목

1. 문서 ID / 담당 AI / 역할 / Prompt Version / Session ID
2. 체크포인트 번호와 작성 시각(시간대 포함)
3. 현재 프로젝트 Phase 및 작업 목표
4. 현재 수행 중인 작업과 진행 상태
5. 확인한 Confirmed 문서와 관련 규칙
6. 확인한 Proposed 문서 및 현재 제안 상태
7. 이번 체크포인트 이후 변경된 파일 경로와 변경 요약
8. 사용자 결정 / 아직 답을 받지 못한 질문
9. 충돌·리스크·REVIEW 필요 여부
10. 다음에 할 정확한 작업 1~3개
11. 재개 시 먼저 읽어야 할 문서 경로
12. 마지막으로 검증한 GitHub 커밋 또는 파일 SHA(확인할 수 있는 경우)

## 6. 상태 표기 규칙

- [CONFIRMED]: 공식 저장소에서 확인된 승인 설정만.
- [PROPOSED]: 승인 전 아이디어, 제안, 사용자 답변 기록.
- [DECISION]: 사용자의 명시적 결정 기록. 결정이 Confirmed 반영됐는지는 별도로 표시.
- [REVIEW]: 검토 요청/검토 결과.
- [UNVERIFIED]: 세션 단절 등으로 원문/저장 여부를 아직 재검증하지 못한 내용.
- [HANDOVER]: 세션 복구용 상태 정보.

Handover 문서에 적혀 있다는 이유만으로 설정을 Confirmed로 간주하지 않는다. 인수인계는 기존 상태를 보존하고 출처 문서를 가리킨다.

## 7. 새 세션 시작 절차

1. 역할 및 최신 역할 Prompt 확인.
2. Confirmed SESSION_PROTOCOL, AI_RULES, SOURCE_OF_TRUTH, SESSION_INDEX, PROJECT_STATUS 확인.
3. Proposed WORKFLOW 및 관련 운영 문서 확인.
4. 자기 AI별 최신 Handover의 Session ID, 체크포인트 번호, 작성 시각 확인.
5. Handover에 기재된 Confirmed/Proposed 원문을 직접 재조회한다.
6. 체크포인트 이후의 변경 커밋/파일을 확인한다.
7. 미해결 사용자 질문과 다음 작업을 확인한다.
8. 상태가 불명확하면 작업을 진행하기 전에 사용자에게 필요한 부분만 확인한다.

## 8. 세션 종료 절차

1. 마지막 체크포인트 이후 변경 사항을 확인한다.
2. 실제로 저장된 파일과 커밋을 재조회한다.
3. 사용자 결정, Proposed, REVIEW, 미해결 질문을 분리한다.
4. 자기 AI별 Handover를 갱신한다.
5. 다음 세션의 시작점과 읽을 문서를 명시한다.
6. 사용자에게 완료한 기록과 미저장/미검증 항목을 보고한다.

## 9. 실패 및 예외 처리

- GitHub 쓰기 실패: 성공했다고 말하지 않는다. 변경 내용을 응답에 보존하고 저장 실패를 명시한다.
- 대화가 갑자기 읽기 전용이 됨: 마지막 체크포인트를 복구 기준으로 삼고, 이후 대화가 확인 가능한 범위만 보충한다.
- 두 Handover가 서로 다름: 최신 작성 시각만으로 무조건 덮어쓰지 않는다. Session ID, 커밋, 원본 파일을 대조하고 충돌을 표시한다.
- 사용자 결정이 상충함: 최신 발언이 기존 결정을 변경하는 명시적 결정인지 확인한다. 모호하면 질문한다.
- 다른 AI의 제안/반론: 원문 Handover를 수정하지 않고 별도 의견으로 기록한다.
- Handover와 Confirmed 원문이 다름: Confirmed 원문을 우선하고 Handover를 수정한다. Canon을 바꾸지 않는다.

## 10. 권장 운영 빈도 요약

- 정기: 10~15회 왕복 또는 30~45분 중 먼저 도달한 시점
- 즉시: 사용자 결정, 중요 파일 변경, 충돌/REVIEW, 세션 전환
- 종료: 매 세션 종료 또는 새 채팅으로 분기하기 전
- 비상: 중단 후 새 세션을 열었을 때 마지막 체크포인트부터 복구

## 11. 기대 효과와 비용

기대 효과:
- 비정상 종료 시 마지막 작업 상태 복구
- 새 채팅/역할 전환 시 반복 설명 감소
- 사용자 결정과 미결정 질문의 혼동 방지
- 저장소 변경과 대화 기억의 불일치 조기 발견

비용/리스크:
- 체크포인트 기록이 지나치게 잦으면 기획 흐름을 방해한다.
- 모든 대화 내용을 기록하면 Handover가 장황해지고 최신 상태를 찾기 어려워진다.
- 시간 기반 주기는 AI가 실제 타이머로 강제할 수 없으므로 권장 트리거로만 사용한다.

완화:
- 변경이 있을 때만 갱신한다.
- 대화 전문 대신 상태와 참조 경로를 기록한다.
- AI별 최신본 한 개를 기본으로 하고 마일스톤만 스냅샷 보존한다.

## 12. 사용자 결정 필요

- 체크포인트 기준: 10~15회 왕복 또는 30~45분 중 먼저 도달한 시점으로 운영할지.
- AI별 최신 Handover 문서에 체크포인트를 통합하고, 별도 로그 파일은 마일스톤에 한해 보존할지.
- Confirmed SESSION_PROTOCOL의 CURRENT_HANDOVER 참조와 Proposed AI별 Handover 구조를 어떻게 연결할지.
- 본 운영안을 REVIEW에 제출할지, 수정 후 제출할지.

## 13. 상태 선언

이 문서는 [PROPOSED]다. 기존 Confirmed SESSION_PROTOCOL, SESSION_INDEX, AI_RULES 및 기존 Handover 문서를 변경하지 않는다. 사용자의 승인 전까지 공식 운영 규칙으로 적용하지 않는다.
