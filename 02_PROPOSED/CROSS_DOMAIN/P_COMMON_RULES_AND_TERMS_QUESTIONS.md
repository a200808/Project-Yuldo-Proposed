# [P] 공통 규칙·용어·상태 정의 질문지

Status: [PROPOSED]
Owner: YULDO-AI-GENERAL (coordination), relevant specialist AIs (content), YULDO-AI-REVIEW (independent review)
Purpose: 서로 다른 파트와 세션이 동일한 용어·전제·상태를 같은 뜻으로 사용하도록 공통 정의가 필요한 항목을 발굴한다.
Canon Notice: 질문과 답변 초안은 사용자 승인 전까지 Proposed다. 이 문서는 세계관·시스템 규칙을 임의로 확정하지 않는다.

## 사용 규칙
- 각 질문에 [OPEN], [PROPOSED], [CONFIRMED], [REVIEW], [N/A] 중 하나를 표시한다. [CONFIRMED]는 사용자 승인된 내용에만 사용한다.
- 이미 Confirmed에 정의가 있으면 재정의하지 말고 공식 출처를 연결한다.
- 용어가 특정 영역에만 속하면 담당 AI가 정의하고, 여러 영역에서 쓰이면 공통 정의와 영역별 사용 규칙을 분리한다.
- 역사적 사실, Confirmed Canon, Proposed, 추론·가설을 섞지 않는다.

## A. 공통 용어와 명명 규칙
- [OPEN] 프로젝트 핵심 용어의 공식 목록은 어디에 유지할 것인가?
- [OPEN] 각 용어에 공식 명칭, 정의, 포함 범위, 제외 범위, 별칭, 플레이어 표시명, NPC 표현, 내부 개발명을 각각 기록해야 하는가?
- [OPEN] 한글 표기·한자 표기·로마자 표기·번역명이 다를 때 기준 표기는 무엇인가?
- [OPEN] 같은 단어가 세계관 용어와 시스템 용어로 다르게 쓰이는 경우 어떻게 구분할 것인가?
- [OPEN] 홍길동, 활빈당, 크로노스, 도술, 축지, 율도국 등 핵심 용어의 범위를 어느 문서가 소유하는가?
- [OPEN] 미정 용어를 임시로 사용할 때 어떤 접두어나 상태 표기를 붙일 것인가?
- [OPEN] 용어 변경이 다른 문서에 미치는 영향을 어떻게 찾아 갱신할 것인가?

## B. 세계관 규칙과 경계
- [OPEN] 세계관 규칙을 어떤 단위로 기록할 것인가: 전제, 법칙, 예외, 금지사항, 알려진 오해?
- [OPEN] 시공간 이동이 가능한 조건, 범위, 비용, 결과, 실패 가능성은 무엇이 Confirmed이며 무엇이 미결정인가?
- [OPEN] 현대 기술이 조선에 존재하거나 사용될 수 있는 조건과 한계는 무엇인가?
- [OPEN] 기술·도술·조선 기술의 상호작용에서 허용, 불허, 조건부 허용을 어떤 방식으로 표시할 것인가?
- [OPEN] 도술의 효과와 한계는 누가 정의하며, 게임플레이 밸런스가 세계관 규칙을 바꿀 수 있는 범위는 어디까지인가?
- [OPEN] 물리적 이동, 축지, 순간 이동처럼 보이는 연출을 어떤 기준으로 구분할 것인가?
- [OPEN] 역사적 사실과 대체역사적 변화가 충돌할 때 어떤 원칙으로 설명하고 기록할 것인가?
- [OPEN] 세계관 규칙이 설명하지 못하는 현상을 허용할 것인가? 허용한다면 미스터리와 설정 누락을 어떻게 구분할 것인가?
- [OPEN] 어떤 행동이나 현상은 세계관상 불가능하다고 명시해야 하는가?

## C. 상태와 변화
- [OPEN] 공통으로 추적해야 하는 상태는 무엇인가: 플레이어, 퀘스트, 지역, 세력, 동료, 자원, 장비, 이야기 진행?
- [OPEN] 각 상태의 값·범위·초기값·변경 조건·영속성은 어떤 문서에서 정의할 것인가?
- [OPEN] 상태 변화가 영구적인지, 임무 내에서만 유효한지, 반복 활동마다 초기화되는지 어떻게 표시할 것인가?
- [OPEN] 같은 사건이 여러 상태를 바꿀 때 처리 순서와 원자성(일부만 성공할 수 있는지)은 어떻게 정할 것인가?
- [OPEN] 상태 변화가 저장·불러오기·재접속 후에도 유지되어야 하는가?
- [OPEN] 지역 해방, 세력 관계 변화, 동료 합류·이탈 등 월드 상태의 시각적·음향적 피드백 기준은 무엇인가?
- [OPEN] 서로 모순되는 상태가 동시에 기록되면 어느 규칙이 우선하는가?

## D. 규칙 우선순위와 예외
- [OPEN] 세계관 규칙, 스토리 연출, 퀘스트 조건, 전투 시스템이 충돌할 때 우선순위는 무엇인가?
- [OPEN] 의도된 예외는 어떤 승인과 문서화 절차를 거쳐야 하는가?
- [OPEN] 정상 흐름 외에 조건 미충족, NPC 부재, 대상 사망, 지역 접근 차단, 임무 중단, 재시도 상황을 공통으로 검토해야 하는가?
- [OPEN] 플레이어가 의도하지 않은 순서로 콘텐츠를 완료하거나 중요한 인물을 먼저 만났을 때 무엇을 보장해야 하는가?
- [OPEN] 같은 결과를 여러 시스템이 동시에 발생시키려 할 때 중복 적용을 허용하는가?
- [OPEN] 설정상 가능한 행동이 시스템상 불가능할 때 이를 수정할지, 세계관적 이유를 부여할지 판단하는 기준은 무엇인가?

## E. 근거와 추적성
- [OPEN] 각 공통 규칙은 어떤 출처, 근거, 결정 기록을 가져야 하는가?
- [OPEN] 역사적 사실 검증이 필요한 항목과 창작 논리 검증이 필요한 항목을 어떻게 구분할 것인가?
- [OPEN] 규칙 변경 시 변경 이유, 영향받는 문서, 검토자, 승인 상태를 어떻게 기록할 것인가?
- [OPEN] 질문에 답이 없을 때 기본값을 추정해도 되는 영역과 반드시 사용자에게 물어야 하는 영역은 무엇인가?
- [OPEN] 상충하는 출처가 발견되면 어떤 절차로 해결할 것인가?

## 완료 판단
- 핵심 용어가 한 가지 공식 정의 또는 명시적 미결정 상태를 가진다.
- 공통 규칙의 가능·불가능·조건부 허용이 구분된다.
- 상태 변화와 규칙 충돌의 우선순위가 필요한 범위에서 정의된다.
- 각 정의의 출처와 승인 상태를 추적할 수 있다.
