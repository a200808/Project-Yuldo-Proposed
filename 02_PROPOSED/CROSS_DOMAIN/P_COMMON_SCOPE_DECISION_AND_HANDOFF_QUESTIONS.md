# [P] 공통 범위·결정·인계 질문지

Status: [PROPOSED]
Owner: YULDO-AI-GENERAL / YULDO-AI-ROUTER; YULDO-AI-REVIEW for independent review
Purpose: 공통 기획에서 지금 결정할 일과 담당 파트로 넘길 일을 구분하고, 세션 분리 후에도 결정 상태와 미결정을 보존한다.
Canon Notice: 이 문서는 운영 제안이다. 승인 전까지 공식 운영 규칙을 변경하지 않는다.

## A. 의사결정 분류
- [OPEN] 어떤 결정은 모든 파트에 영향을 주므로 공통 기획에서 먼저 다뤄야 하는가?
- [OPEN] 어떤 결정은 담당 파트가 대안을 만든 뒤 GENERAL/REVIEW/사용자에게 가져와야 하는가?
- [OPEN] 어떤 결정은 사용자의 직접 선택 없이는 진행할 수 없는가?
- [OPEN] 어떤 항목은 사용자 선택 전까지 여러 Proposed 대안을 병렬로 유지할 수 있는가?
- [OPEN] 결정의 중요도를 차단 결정, 상위 전제, 영역 결정, 세부 조정으로 구분할 것인가?
- [OPEN] 답이 미정이어도 다음 작업을 진행할 수 있는 질문과 진행을 막는 질문을 어떻게 구분할 것인가?

## B. 범위와 우선순위
- [OPEN] 현재 Phase의 핵심 질문에 직접 연결되지 않는 주제를 어떻게 분리할 것인가?
- [OPEN] 논의가 다른 방향으로 흐를 때 보류 목록에 기록할 최소 정보는 무엇인가?
- [OPEN] 중복 아이디어, 이미 검토된 대안, 기존 Canon과 충돌 가능성이 있는 제안을 어떻게 식별할 것인가?
- [OPEN] 상세 수치와 구현을 지금 다뤄야 하는 예외 조건은 무엇인가?
- [OPEN] 콘텐츠 규모가 커질 때 핵심 경험을 보존하면서 범위를 줄이는 우선순위는 무엇인가?
- [OPEN] 개발 비용이 큰 제안을 채택하기 전에 요구할 근거와 대체안은 무엇인가?

- [OPEN] 사용자의 승인 표현이 모호할 때 어떤 조건에서 확정으로 처리할 것인가?
- [OPEN] 검토 결과와 사용자의 최종 결정을 어떻게 구분할 것인가?

- [OPEN] 한 결정이 다른 결정을 전제로 한다면 그 의존성을 어떻게 표시할 것인가?

- [OPEN] 새 세션이 인계 자료와 공식 저장소 사이에서 충돌을 발견하면 어떤 순서로 확인할 것인가?
- [OPEN] 전문 AI가 공통 전제를 수정하고 싶을 때 제안·영향 분석·승인 요청을 어떤 방식으로 제출하는가?
- [OPEN] 전문 AI가 공통 기획 범위 밖의 아이디어를 발견했을 때 어느 Proposed 경로에 기록하는가?
- [OPEN] 인계가 완료되었다고 판단할 조건은 무엇인가?

- [OPEN] 공통 기획 종료 후에도 계속 유지할 변경 관리·질문 이관·충돌 검수 절차는 무엇인가?

## 완료 판단
- 공통 결정과 파트별 결정의 경계가 명시되어 있다.
- 사용자 승인, REVIEW, Proposed, Confirmed의 역할이 구분되어 있다.
- 세션 인계 시 미결정과 출처가 손실되지 않는다.
- 공통 기획 종료 기준이 문서 작성 완료가 아니라 다음 단계의 작업 가능성으로 검증된다.
