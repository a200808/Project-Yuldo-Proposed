# AI 작업 사례집

상태: [PROPOSED]

## 목적

실제 프로젝트 대화와 작업 결과에서 좋은 사례와 나쁜 사례를 선별하여 AI가 프로젝트의 작업 방식을 학습할 수 있도록 한다.

규칙만 나열하는 것보다 실제 사례를 통해 원하는 판단 방식과 금지되는 행동을 명확히 보여주는 것을 목표로 한다.

## 사례 유형

### GOOD_PROPOSAL

좋은 기획 제안 사례.

포함:
- 문제 정의
- 기존 설정 확인
- 제안
- 근거
- 리스크
- 대안
- 미확정 사항

### GOOD_REVIEW

좋은 검수 사례.

포함:
- 검토 대상
- Confirmed/Proposed 대조
- 충돌
- 개연성
- 시스템 영향
- 수정안
- 판단 근거

### GOOD_DISAGREEMENT

사용자 또는 다른 AI의 의견에 논리적으로 반대하면서도 생산적인 대안을 제시한 사례.

### GOOD_CANON_CHECK

기존 Canon을 먼저 확인하고 새 제안과 충돌 여부를 판단한 사례.

### BAD_AI_BEHAVIOR

다음과 같은 실패 사례를 보존한다.

- 근거 없는 칭찬
- 사용자 의견에 자동 동조
- Proposed를 Confirmed처럼 취급
- 기존 문서를 확인하지 않고 새 설정 생성
- 문제를 발견하고도 숨김
- 역사/세계관/시스템 충돌을 무시
- 구현 단계로 너무 빨리 넘어감
- 불필요하게 장황한 관리 절차를 제안하여 기획을 방해함

## 사례 선정 원칙

실제 대화에서 사례를 추출하는 것을 우선한다.

가공된 예시를 만들 경우 실제 프로젝트의 Confirmed 설정처럼 읽히지 않도록 명시한다.

## 사례의 역할

사례집은 프로젝트의 Canon이 아니다.

사례는 AI 행동 방식의 참고 자료이며, Canon/Proposed/Review/Decision 문서보다 우선하지 않는다.
