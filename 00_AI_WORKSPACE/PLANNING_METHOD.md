# 프로젝트 율도 기획 진행 방식

## 문서 정보

- 작성 AI: YULDO-AI-GENERAL
- AI 역할: GENERAL
- Prompt Version: GENERAL-v1.0
- 작성일: 2026-09-08
- 상태: [PROPOSED]

## 1. 목표

프로젝트 율도의 초기 기획은 세부 콘텐츠를 빠르게 양산하는 것보다, 전체 구조가 서로 충돌하지 않는 상태를 먼저 만드는 것을 목표로 한다.

핵심 원칙은 다음과 같다.

`큰 뼈대 → 영역별 제안 → 교차 검토 → 사용자 결정 → Canon 반영 → 세부화`

## 2. 기획 단계

### Phase 0 — 기획 운영체계 준비
- AI 역할 확정
- 공통 초기 프롬프트 확정
- 각 AI의 작업 프롬프트 확정
- Proposed 저장 규칙 확정

### Phase 1 — 핵심 기획 골격
다음 질문에 답할 수 있는 수준까지 먼저 만든다.
1. 이 게임은 무엇을 하는 게임인가?
2. 플레이어는 누구이며 무엇을 원하는가?
3. 세계의 핵심 갈등은 무엇인가?
4. 홍길동의 중심 서사는 무엇인가?
5. 게임의 핵심 반복 루프는 무엇인가?
6. 플레이어가 성장하는 방식은 무엇인가?
7. 한 번의 플레이에서 무엇을 하고 무엇을 얻는가?

이 단계에서는 세부 수치, 수많은 무기, 수많은 NPC/퀘스트를 만들지 않는다.

### Phase 2 — 영역별 골격
WORLD / STORY / QUEST / GAMEPLAY / EQUIPMENT / ALLIES / NPC_FACTIONS / CONTENT가 각각 자신의 골격을 제안한다.

각 AI는 작업 전 Confirmed와 Proposed의 관련 문서를 확인하고, 다른 영역과 충돌할 가능성을 명시한다.

### Phase 3 — 교차영역 통합
교차영역 문제는 CROSS_DOMAIN 또는 관련 AI 간 의견 문서로 다룬다.

예:
- STORY ↔ QUEST
- WORLD ↔ GAMEPLAY
- GAMEPLAY ↔ EQUIPMENT
- STORY ↔ NPC_FACTIONS
- QUEST ↔ ALLIES

### Phase 4 — REVIEW
REVIEW AI가 다음을 검토한다.
- Confirmed와의 충돌
- Proposed 간 충돌
- 세계관 개연성
- 역사적 사실과의 충돌 여부
- 게임 디자인상 문제
- 다른 시스템에 미치는 영향
- 지나치게 복잡한 설계 여부

REVIEW는 판결 자료를 만들지만 Canon을 확정하지 않는다.

### Phase 5 — 사용자 결정
사용자가 승인/수정/보류/폐기한다.

결정은 DECISION 기록으로 남기고, 승인된 내용만 Confirmed 저장소로 이관한다.

### Phase 6 — 세부화
큰 구조가 안정된 뒤에만 다음 단계로 내려간다.
- 세부 시스템
- 세부 지역
- 세부 캐릭터
- 퀘스트
- 무기
- 성장 수치
- 밸런스
- 구현 명세

## 3. AI 운영 방식

모든 AI는 같은 GitHub 계정을 사용하므로 GitHub commit author만으로 작업자를 식별하지 않는다. 모든 작업 문서에 AI identity와 Prompt Version을 기록한다.

원 제안은 덮어쓰지 않는다. 다른 AI가 반대하거나 수정 의견을 가지면 `other_ai_proposed`에 독립 문서를 만든다.

## 4. 브레인스토밍 규칙

브레인스토밍 기간에는 승인되지 않은 결과를 모두 Proposed에 축적한다.

단, 모든 아이디어를 정식 제안서로 만드는 것은 금지하지 않는다. 단순 아이디어는 INBOX에 남길 수 있으며, 검토할 가치가 생겼을 때 정식 Proposed로 발전시킨다.

## 5. 중요한 운영 원칙

- AI는 사용자의 승인 없이 Canon을 확정하지 않는다.
- 기존 설정과 충돌하면 조용히 수정하지 않고 충돌을 표시한다.
- 각 AI는 자기 영역만 책임지는 것이 아니라, 자기 제안이 다른 영역에 미치는 영향을 함께 표시한다.
- 문서 관리가 실제 기획보다 복잡해지지 않도록 한다.
- 큰 의사결정이 끝나기 전에는 세부 수치와 구현으로 내려가지 않는다.

## 6. 권장 작업 단위

한 번에 전체 게임을 만들지 않는다.

`질문/문제 → 관련 자료 확인 → 담당 AI 제안 → 대안/반론 → REVIEW → 사용자 결정`

이 과정을 핵심 의사결정 단위마다 반복한다.
