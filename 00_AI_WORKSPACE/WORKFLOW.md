# AI WORKFLOW

상태: [PROPOSED]

## 1. 기본 처리 흐름

사용자 아이디어 → MAIN/ROUTER → 담당 AI 제안 → 즉시 Proposed 기록 → 다른 AI 의견 → REVIEW → 사용자 결정 → Confirmed 이관

## 2. AI 부팅 규칙

AI가 프로젝트 율도에서 역할 이름을 부여받으면 가장 먼저 GitHub의 자신의 역할 Prompt를 읽는다. Prompt를 읽기 전에 기획 작업을 시작하지 않는다.

행동 지침 우선순위:
1. 현재 적용되는 YULDO AI 역할 Prompt
2. 프로젝트 공통 AI 운영 규칙
3. Confirmed Canon
4. Proposed
5. Handover / Chat Log / Examples
6. 일반적인 AI 습관이나 추정

Prompt는 AI의 행동을 규정하고 Canon은 게임의 공식 설정을 규정한다.

## 3. 저장소 역할

- a200808/Project-Yuldo: 사용자 승인 공식 Canon 및 Source of Truth
- a200808/Project-Yuldo-Proposed: 브레인스토밍, 제안, 대안, 검토 및 결정 대기 기록

## 4. 읽기 원칙

모든 AI는 작업 전에 Confirmed와 Proposed의 관련 내용을 확인한다. 자기 담당 폴더만 보고 아이디어를 생산해서는 안 된다.

## 5. 즉시 Proposed 기록 원칙

기획 작업에서 생성된 의미 있는 내용은 가능한 한 작업 즉시 Proposed에 기록한다.

나중에 한꺼번에 정리하는 것을 기본 방식으로 사용하지 않는다.

기록 대상:
- 새로운 아이디어
- 기존 제안 수정
- 대안
- 반론
- 확장안
- 시스템 규칙
- 스토리/세계관 구조
- 콘텐츠 정의
- 중요한 문제와 리스크
- 다른 영역에 영향을 주는 결정 후보

기본 흐름:
생성 → 즉시 Proposed 기록 → 검토 → 사용자 결정 → 필요 시 Confirmed 반영

즉시 기록 ≠ 즉시 확정

## 6. 쓰기 원칙

담당 AI는 Proposed의 자기 영역에 제안서를 작성한다.
다른 AI는 원 제안 문서를 직접 덮어쓰지 않는다.
다른 의견은 해당 영역의 other_ai_proposed에 독립 문서로 작성한다.
기존 문서를 수정할 경우 먼저 읽고 변경 이유와 변경 이력을 기록한다.

## 7. REVIEW

REVIEW는 독립 검토 기능을 담당한다. Confirmed와 Proposed를 대조하여 충돌, 설정 모순, 시스템 문제, 개연성, 누락 등을 검토한다. REVIEW 자체가 Canon을 확정하지 않는다.

## 8. 최종 승인

최종 승인 권한은 사용자에게 있다. REVIEW의 적합 판정과 사용자 승인은 별개의 단계다.

## 9. 기록 원칙

모든 실질적인 제안·의견·검토에는 문서 ID, 작성 AI, AI 역할, Prompt Version, 작성일, 상태를 기록한다.

## 10. 브레인스토밍 기간

브레인스토밍이 끝날 때까지 결과는 Proposed에 계속 축적한다. 브레인스토밍 중에는 Confirmed로 자동 승격하지 않는다.

## 11. 최종 통합

최종 단계에서는 개별 문서를 단순 병합하지 않는다. 영역 간 연결, 충돌, 누락, 용어, 시스템 로직, 플레이어 경험, 예외 상황을 검수한 후 최종 통합 게임 기획서로 정리한다.
